Architecture

One request that matters, cached at the edge

Rutgers publishes an unauthenticated list of currently-open section indexes. WebReg accepts a registration index pre-filled in the URL. Everything here exists to close the gap between a seat opened and you have a registration form loaded.

Why the split

Course titles, professors and meeting times change roughly never during a term, so they are built once a day into a static file and served from a CDN. Only the open/closed set is live, and it is 26 KB. The page is not re-downloading 4.8 MB every thirty seconds — it fetches a small array of index numbers and diffs it in memory.

The diff is what makes it edge-triggered: a section that was already open does not re-announce itself. V1 solved that problem with a per-user ten-minute cooldown; comparing against the previous set removes the need for one.

Findings

What the undocumented API actually does

Rutgers publishes no API documentation. Everything below was established by inspection, and each one changed a design decision.

courses.json ignores its own subject parameter

One request returns the entire campus catalogue. V1 drove a headless Chrome browser across fifteen school pages, waiting ten seconds each, to scrape a subset of the same data out of rendered HTML — data the page had itself fetched as JSON moments earlier. That pipeline is gone.

Index numbers are recycled between terms

3,059 index numbers from Spring 2025 also appear in Fall 2026 — attached to entirely different courses. 10052 is LITERARY EGYPT this term and was something else last term. Any stored history has to be scoped per term or it silently corrupts at every rollover.

Cross-listed sections open independently

Of 970 cross-listed pairs in Fall 2026, 254 are currently split — one index open, its twin closed. They are the same class under two department codes, but the seat pools track separately, so watching one does not cover the other.

24% of sections need a special permission number

2,902 of 12,004 New Brunswick sections carry a non-null specialPermissionAddCode. An open seat in one of those is not registrable without departmental approval, so they are badged SPN rather than treated as a normal opening.

No CORS headers, and a 30-second cache

The endpoints send no Access-Control-Allow-Origin, so a browser cannot call them from a page — hence the proxy. They also advertise Cache-Control: max-age=30, which sets the floor on useful polling. An ETag is sent but If-None-Match is ignored, so conditional requests buy nothing.

Course titles are aggressively abbreviated

Expository Writing is filed as COLLEGE WRITING; you will also find MICROBIOL HLTH SCI and ADV ORGANIC CHEM I. Exact matching returns nothing for the names students actually type, so search is relevance-ranked instead — tokens scored independently across index, code, title, instructor and subject, with abbreviations expanded and stopwords dropped.

About

What this is, and what it isn't

RU SnipeZ watches Rutgers course sections and tells you the moment a seat opens — with the registration link already filled in. This page is the live, public demo of the monitoring engine.

What you're looking at

Everything on the Monitor tab is real data, right now. The catalogue is built daily from the Rutgers Schedule of Classes API, and the open/closed status refreshes every thirty seconds against the live endpoint. Pressing Watch shows you exactly the alert you would receive, including a working WebReg link with the index pre-filled.

Honest limitation

This demo watches sections only while this tab is open. Your watchlist is stored in your own browser and never leaves it, which also means it does not follow you to another device. Real background alerts — push notifications that reach you with the tab closed — need an always-on server, and that is the next milestone rather than something this page does today.

Things worth knowing before you rely on it

  • A section badged SPN needs a special permission number from the department. An open seat there is not registrable on its own — and that is 24% of New Brunswick sections.
  • A section badged XL is cross-listed under a second department code with its own index. The two open and close independently, so it is usually worth watching both.
  • Open/closed reflects what the university's own endpoint reports, cached up to thirty seconds. It is as current as the Schedule of Classes website is.
  • Outside registration periods most sections sit still, so the activity feed will mostly log quiet polls. That is the system working, not a bug.

Where it stops, deliberately

RU SnipeZ notifies. It does not register for you, and it never asks for, stores, or transmits a NetID or password. You sign in to WebReg through CAS yourself, exactly as you normally would — the only thing the link does is save you from typing the index. That line is a design constraint, not an unfinished feature.

It reads the same public endpoints the Schedule of Classes website reads, caches responses at the edge so one request serves every visitor, and polls no faster than the university's own cache header invites.

Built by

A Rutgers student who got tired of refreshing WebReg. V1 ran as a Discord bot serving a student community; this is the rebuilt engine behind it, now with a public interface. The full source, including the architecture notes and the API findings on the How it works page, is on GitHub.
